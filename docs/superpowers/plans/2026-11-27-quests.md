# Quests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Timed, opt-in quests: a live event can raise an offer banner; accepting starts a timer pill; finishing the ordered steps in time pays exp × a chain multiplier, failing breaks the chain.

**Architecture:** Quest definitions, state machine and persistence live in `rpg-core` (new `quests` module, store schema v4). The engine advances the active quest inside each event's transaction and records `quest_completed` / `quest_failed` events that rules can count. `rpg-app` decides *when* to offer (DND, toggle), runs the deadline timer and the early GitHub poll on the inbox thread, and renders the offer banner, timer pill and character-sheet section.

**Tech Stack:** Rust (rusqlite, serde/toml, chrono, globset), Tauri 2 overlay windows (HTML/CSS/JS), axum site.

**Spec:** `docs/superpowers/specs/2026-11-27-quests-design.md` (look reference: `docs/superpowers/specs/2026-11-27-quests-prototype.html`, style A).

## Global Constraints

- All `engine`/store writes happen on the `rpg-inbox` thread (`Store::begin_tx` assumes single-threaded processing). UI actions (accept, pass, toggle) reach it as `Msg`s.
- Quest files live in **`<config>/rules/quests/`** (`Paths::quests()`), following `rules/skills/`, so "Open rules folder" reaches them. *(Plan decision; the spec said "next to `rules/`".)*
- Quest TOML: unknown fields are load errors; bad files are skipped and logged; duplicate ids, first wins; files load in filename order.
- `[quests]` defaults: `enabled = true`, `offer_seconds = 60`, `max_passes = 3`, `chain_step = 0.5`, `chain_max = 5.0`, `min_gap_minutes = 30`.
- Multiplier = `min(1 + chain_step × n, chain_max)`, `n` = completions in a row; reward = `floor(xp × multiplier)`.
- Quest exp default = `Tier::default_xp() / 2` (125 / 250 / 500 / 1,000 / 2,000 / 4,000).
- Offers only from events with `!backfill`, not in the startup away batch, `now − ts ≤ 5 min`, no active quest and no pending offer, quests on, DND off.
- Steps count only events with `accepted_at ≤ ts ≤ deadline`, in order, `count` each (default 1).
- Quest colors: crimson `#ff4d5e`, ember `#ff9a3c`; tier palette is the existing one in `ui/overlay/overlay.css`.
- `quest_completed` / `quest_failed`: `Source::Quest`, `repo = None`, no base exp, never trigger quests.
- `prefers-reduced-motion`: fade only (as banners today).

## Review Focus

1. **Toast window auto-hide.** `TOAST_HIDE_AFTER` hides the toast window 3.6 s after the last pill; an active quest's pill must keep it visible (test in Task 7).
2. **Quest file edited or deleted mid-quest.** Rules hot-reload must not strand an active quest: it advances and resolves from the step snapshot stored in its row (test in Task 4).
3. **Duplicate delivery.** The same event id processed twice (inbox retry, GitHub re-poll) must not count a step twice (test in Task 4).
4. **Stale events raising offers.** Startup away batch, backfill, and events older than 5 min never raise an offer, nor events from `[paths] exclude`d repos (tests in Tasks 4 and 5).
5. **Event history mislabels quest exp.** The reward's ledger row has no `unlock_id`; the character sheet must show it as quest exp, not as an achievement or base exp (test in Task 8).

- Produces in `engine`:
  - `Outcome.quest: Option<QuestView>` — set when this event advanced or completed the active quest.
  - The quest reward is an `XpGain { label: "Quest: <name>", achievement: None, .. }` and a ledger row with reason `"Quest: <name>"`, `unlock_id = None`, against the `quest_completed` event id.
  - `pub fn expire_quest(store: &Store, rules: &Rules, cfg: &Config, now: DateTime<Utc>, tz: FixedOffset) -> Result<Option<(Event, Outcome, QuestView)>>` — in one transaction: if the active quest's `deadline < now`, mark it `failed`, reset chain n to 0, record a `quest_failed` event, run rules on it.

Matching algorithm (in `state.rs`, called from `process_inner` after `insert_event` succeeded and the event is not backfill and not a quest kind): take `active_quest`; if `ev.ts` is outside `[accepted_at, deadline]` stop; find the first step with `have < need`; if `ev.kind` equals its kind, its filter matches, and the binding matches (`repo`: same resolved repo; `branch`: same repo and `data.branch`; `pr`: `data.url == pr_url`), increment it. When every step is full: status `completed`, chain n += 1 (best = max), build the `quest_completed` event (`data`: `quest_id`, `tier`, `chain` = new n, `multiplier`, `xp` = reward), `insert_event` + `records::update`, ledger row, then run the rule loop on it. Matching reads the **row's `steps` snapshot**, never the current `QuestDef`.

### Task 5: Runtime: offers, deadline, early GitHub poll, toggle

**Files:**
- Modify: `crates/rpg-app/src/runtime.rs`, `crates/rpg-app/src/main.rs`, `crates/rpg-app/src/tray.rs`, `crates/rpg-app/src/overlay.rs` (trait impl stubs only)

**Interfaces:**
- Consumes: Task 4 `offer_for`, `accept`, `pass`, `cancel`, `active_view`, `expire_quest`, `QuestView`, `Offer`.
- Produces:
  - `OutcomeSink` gains `fn offers_allowed(&self) -> bool`, `fn quest_offer(&self, id: u64, offer: Offer)`, `fn quest_update(&self, view: QuestView)`, `fn quest_offer_withdrawn(&self, id: u64)`.
  - `pub struct Runtime { tx: Sender<Msg> }` (Clone), returned by `spawn`, `app.manage`d; methods `answer_offer(&self, id: u64, accept: bool)`, `drop_offer(&self, id: u64)` (no pass), `set_quests_enabled(&self, on: bool)`.
  - `Toggles.quests: AtomicBool`, initialised from `cfg.quests.enabled`.

Behavior on the inbox thread: a pending offer `Option<(u64, Offer, Instant)>`. After each **live** (`away == false`) batch, if `sink.offers_allowed()` and quests are on and nothing is pending, call `offer_for` per event in order with `roll = fastrand::f64` until one returns `Some` → `sink.quest_offer`. `answer_offer(accept)` → `accept` + `sink.quest_update(Active)` + poke GitHub if `has_github_step`; `answer_offer(false)` → `pass`. A pending offer older than `offer_seconds + 300 s` is dropped without a pass. Deadline: `recv_timeout` waits at most until the active deadline; past it, if the quest has an unfinished GitHub step and GitHub is enabled and not yet checked, send `Checking`, poke the poller and wait for its next `Wake` (cap 30 s), then `expire_quest` → `sink.quest_update(Failed)` and `sink.present` for its unlocks. Startup: after the away batch, run the same deadline check, then re-send the active quest's view. `set_quests_enabled(false)` → `cancel` + `Cancelled` view + withdraw a pending offer. GitHub thread: replace its `sleep` with `recv_timeout` on a poke channel.
