# RPG v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local Tauri tray app that turns git, GitHub and Claude Code activity into XP, levels and data-defined achievements, announced through corner XP pop-ups, Gold Banners with sound, and a localhost character-sheet site.

**Architecture:** A Cargo workspace with three pieces:
- `rpg-core`: a pure library with events, inbox, SQLite store, rules, detectors, engine, flavor, GitHub parsing and hook installers. It has no Tauri dependency, so almost everything is unit-testable.
- `rpg-cli`: a tiny `rpg` binary that hooks call (`rpg emit …`, `rpg install-hooks`).
- `rpg-app`: the Tauri v2 tray app. It drains the inbox, polls GitHub, runs the engine, drives the overlay windows and serves the site.

Hooks only drop event files into an inbox, and the app processes them whenever it runs.

**Tech Stack:** Rust (stable), Tauri 2 (`tray-icon` feature), rusqlite (`bundled`), serde/serde_json, toml, chrono, ulid, directories, notify, clap, axum + tokio, rust-embed, rodio, wait-timeout, which, anyhow, tempfile (tests). The UI is plain HTML/CSS/JS with no framework.

**Spec:** `docs/superpowers/specs/2026-11-23-xp-achievements-design.md`

**Decision vs spec:** the spec says the emitter is "a subcommand of the app binary". This plan puts it in a separate small `rpg` CLI binary instead. A Tauri GUI binary is built with the Windows GUI subsystem, so it has no console output and pays webview-related startup costs. The spec left the emitter mechanism to the builder.

## Global Constraints

- Hooks must be fast, must **never fail a git operation**, and must pass through to the repo's own hooks. `rpg emit` always exits 0 and logs errors to `<data>/rpg.log`.
- Overlay windows are transparent, borderless, always on top, never take focus, are hidden from the taskbar/Dock, and are click-through. The only exception: the banner can be clicked to dismiss.
- Nothing leaves the machine except the optional `claude -p --model haiku` flavor call. Its context holds only event type, repo name, branch, achievement name and detector findings (file path, ages, counts), never code or diffs. `llm.enabled` turns it off.
- Banners show one at a time and queue. Frequent events only produce XP pop-ups.
- Backfilled GitHub history seeds records and baselines only. It grants **no XP and no achievements**, and the character starts at level 1.
- Default XP: commit 10, push 25, PR opened 50, PR merged 100, review 40, Claude session completed 15. All of these live in config.
- Cumulative XP needed to reach level n is `round(100 * (n-1)^1.5)`, so level 1 starts at 0 XP. The base and exponent live in config. (This interprets the spec's `round(100 * n^1.5)` so that a new character starts at level 1 with 0 XP.)
- XP pop-ups show bottom-right on the primary display for ~3s, stacking upward. The Gold Banner (style B) shows top-center for ~8s or until clicked.
- LLM flavor text has a ~10s timeout, then falls back to the rule's `fallback`. Generated text is stored with the unlock. It's per-rule opt-in (`flavor` defaults to `static`).
- Every subprocess the app spawns (`git`, `gh`, `claude`) uses `CREATE_NO_WINDOW` on Windows, through one helper (`rpg_core::proc::command`). No console windows may flash.
- Platform-specific code lives only in `rpg_core::proc` and `rpg-app/src/platform.rs`. v0 is verified on Windows 11, and the code must stay portable to macOS.
- Paths come from `directories::ProjectDirs::from("", "", "rpg")`: the data dir holds `rpg.db`, `inbox/`, `git-hooks/` and `rpg.log`; the config dir holds `config.toml`, `rules/` and `sounds/`. Env var `RPG_HOME`, when set, puts both under `$RPG_HOME/data` and `$RPG_HOME/config`. This is used by tests.
- Env var `RPG_INTERNAL=1` makes `rpg emit` a no-op. The app sets it on every `claude` subprocess.

## Review Focus

1. **A repo's existing `.git/hooks/*` (pre-commit, commit-msg, …).** Setting a global `core.hooksPath` silently stops those hooks from running. The user expects their repo's hooks to keep working exactly as before, so we install pass-through shims for *every* git hook name, not just the two we use. Test: Task 8 `failing_repo_precommit_still_blocks_commit`.
2. **Our own `claude -p` flavor call firing Claude Code's SessionStart/SessionEnd hooks.** That would award XP for our own calls and could loop. The user expects these calls to be invisible. Test: Task 1 `emit_is_noop_when_rpg_internal_set`.
3. **The `rpg` binary missing or moved, or the inbox unwritable.** The user expects `git commit` and `git push` to succeed normally anyway. Test: Task 8 `commit_succeeds_when_rpg_binary_missing`.
4. **A malformed rule TOML**, e.g. saved mid-edit while hot reload is watching. The user expects that file to be skipped with a log line, and every other rule to keep working. Test: Task 3 `bad_file_is_skipped_others_load`.
5. **The app closed for days (or a single event triggering a pile of unlocks).** The user expects at most 3 banners, the *biggest* ones, plus one "…and N more" summary, not a flood. Tests: Task 10 `away_batch_caps_banners`, `live_storm_caps_and_sorts`.

### Task 1: Events, inbox and `rpg emit`

**Files:**
- Create: `crates/rpg-core/src/{event.rs,inbox.rs,emit.rs}`, `crates/rpg-cli/{Cargo.toml,src/main.rs}`

**Interfaces:**
- Consumes: `Paths`
- Produces:
  - `enum EventKind { Commit, Push, PrOpened, PrMerged, ReviewSubmitted, ClaudeSessionStart, ClaudeSessionEnd }`, serialized snake_case, with `as_str()`
  - `enum Source { Git, Github, Claude }`
  - `struct Event { id: String, kind: EventKind, ts: DateTime<Utc>, source: Source, repo: Option<String>, backfill: bool, data: serde_json::Value }`
  - Commit `data`: `{ hash, branch, repo_path, files: [{path, added, removed}], lines_added, lines_removed }`
  - Push `data`: `{ remote, branch, repo_path }`
  - Claude `data`: `{ session_id, cwd }`
  - GitHub `data`: see Task 7
  - `inbox::write_event(inbox: &Path, ev: &Event) -> Result<()>`: writes `<ulid>.json.tmp`, then renames it to `<ulid>.json`
  - `inbox::drain(inbox: &Path) -> Result<Vec<(PathBuf, Event)>>`: returns parsed events sorted by filename. Unparseable files move to `inbox/bad/`. The caller deletes each file after processing it.
  - `emit::commit_event(repo: &Path, hash: &str) -> Result<Event>`: uses `git show --numstat --format= <hash>` and `git rev-parse --abbrev-ref HEAD`. Binary files (`-` counts) count as 0.
  - `emit::push_event(repo: &Path, remote: &str) -> Result<Event>`
  - `emit::claude_event(kind: EventKind, stdin_json: &str) -> Result<Event>`: reads `session_id` and `cwd` from the hook's stdin JSON
  - `rpg` CLI: `rpg emit commit --repo <p> --hash <h>`, `rpg emit push --repo <p> --remote <r>`, `rpg emit claude-session-start` / `claude-session-end` (stdin), `rpg install-hooks`, `rpg uninstall-hooks` (wired in Task 8)
  - Event ID scheme: git/claude use `ulid`. GitHub uses deterministic IDs (Task 7).

### Task 4: Records and detectors

**Files:**
- Create: `crates/rpg-core/src/{records.rs,detectors.rs,enrich.rs}`
- Test: in-module tests; `tests/enrich.rs` (real git)

**Interfaces:**
- Consumes: `Store`, `Event`, `Detector`, `Metric`
- Produces:
  - `records::update(store: &Store, ev: &Event) -> Result<Vec<RecordBroken>>`, where `RecordBroken { metric: Metric, old: f64, new: f64 }`. It computes each metric relevant to `ev.kind` and stores it whenever it's higher than the old value. It returns a break only when a previous value existed and the new one is strictly greater, so a first-ever value seeds without counting as a break.
  - `enrich::file_ages(repo: &Path, hash: &str, files: &[String], cap: usize /*50*/) -> Result<Vec<FileAge { path, years: f64, last_author: String }>>`. For each file it runs `git log -1 --format=%ct%x09%an <hash>^ -- <path>`. Files with no prior history are omitted.
  - `detectors::evaluate(det: &Detector, ctx: &EvalCtx) -> Result<Option<serde_json::Value>>`. `Some(findings)` means the rule fired, and the findings become the LLM context.
  - `EvalCtx<'a> { ev: &'a Event, store: &'a Store, broken: &'a [RecordBroken], file_ages: &'a [FileAge], tz: chrono::FixedOffset }`
  - Semantics:
    - `count_in_window` fires when the count today including this event equals `count` exactly, so it fires once per day. Findings: `{count}`.
    - `personal_record` fires if `broken` contains its metric. Findings: `{metric, old, new}`.
    - `file_age` fires on the oldest file with `years >= min_years`. Findings: `{path, years, last_author}`.
    - `time_of_day` uses the event's local hour. Findings: `{hour}`.
    - `diff_size` uses `lines_added + lines_removed` for commits, or `additions + deletions` for PRs. `min_delete_ratio` = deletions / total. Findings: `{added, removed}`.
    - `first` uses `!store.has_prior_event(kind, scope==Repo ? repo : None, ev.id)`. Findings: `{repo}`.

### Task 5: Engine

**Files:**
- Create: `crates/rpg-core/src/engine.rs`
- Test: in-module tests with an in-memory store and rules built in code

**Interfaces:**
- Consumes: everything from Tasks 2–4, plus `Config`
- Produces:
  - `engine::process(store: &Store, rules: &Rules, cfg: &Config, ev: &Event, file_ages: &[FileAge]) -> Result<Outcome>`
  - `Outcome { xp_gains: Vec<XpGain>, unlocks: Vec<Unlock>, level_ups: Vec<u32>, total_xp: u64, level: u32 }`
  - `XpGain { amount: u64, label: String }`, e.g. `"PR opened"`
  - `Unlock { unlock_id: i64, rule_id, name, tier: Tier, xp: u64, findings: serde_json::Value, unlock_count: u32, last_unlocked_at: Option<DateTime<Utc>> }`
  - Order of operations:
    1. `insert_event`. On a duplicate, return an empty `Outcome`.
    2. `records::update`.
    3. If `ev.backfill`, return here: records are seeded, with no XP and no unlocks.
    4. Add base XP by kind. `ClaudeSessionStart` gets 0. `ClaudeSessionEnd` gets `claude_session` only when a matching start exists.
    5. For each `rules.for_kind`: skip if it's not repeatable and `unlock_count > 0`; skip if within the cooldown; otherwise `evaluate`, and on `Some`, `insert_unlock` and add the rule's XP.
    6. Compute level-ups between the levels before and after.
  - `unlock_count` in `Unlock` includes this unlock.

    - The hook names: applypatch-msg, pre-applypatch, post-applypatch, pre-commit, pre-merge-commit, prepare-commit-msg, commit-msg, post-commit, pre-rebase, post-checkout, post-merge, pre-push, pre-receive, update, post-receive, post-update, push-to-checkout, pre-auto-gc, post-rewrite, sendemail-validate, fsmonitor-watchman, p4-changelist, p4-prepare-changelist, p4-post-changelist, p4-pre-submit, post-index-change, reference-transaction.

  - `install::uninstall_claude_hooks(settings_path) -> Result<()>`: removes only the entries whose command contains `emit claude-session-`.
  - Shim template behavior (`__RPG_BIN__`, `__HOOK__` and `__PREV__` substituted at install; Windows paths with forward slashes):

If the hook is `pre-push`, run `rpg emit push --repo … --remote "$1"` the same way. Skip this step if the binary doesn't exist.
    2. Chain: the target is `__PREV__/__HOOK__` if `__PREV__` is non-empty, else `"$(git rev-parse --git-common-dir)/hooks/__HOOK__"`. If it's executable, `exec "$next" "$@"`, which inherits stdin and so preserves exit code and stdin for pre-push.
    3. Otherwise `exit 0`.
